# シフト自動生成（ソルバー / Claude）

管理画面「シフト作成」で、スタッフの希望・必要人数・固定シフト・社保加入状況をもとに
月次シフトを自動生成する。2つのエンジンがある。

| エンジン | ファイル | 特徴 |
|---|---|---|
| ソルバー（貪欲法） | `src/lib/shift-generator/solver.ts` | 制約を厳密に守る。必要人数(shift_requirements)ベース |
| Claude生成 | `src/lib/shift-generator/claude-generator.ts` ＋ `src/lib/shift-prompt.ts` | 店舗ルール＋LLMで柔軟に編成 |

どちらも同じ入力（スタッフ・希望・承認済み休み・個別予定・**固定シフト**）を受け取り、
`shifts` に `ai_generated=true` で保存する。

## 入力データ

- **スタッフ** `profiles`（在籍中のみ）：`min/max_hours_per_week`、**`shaho_enrolled`（社保加入）**、
  **`standard_shift_hours`（1日の所定勤務時間・拘束）**。
- **希望シフト** `availability_preferences`：曜日ごとの preferred / available / unavailable。
- **承認済みお休み** `time_off_requests`（status=approved）＋ **個別予定** `staff_blackouts`（不可時間）。
- **必要人数** `shift_requirements`（曜日×時間帯×人数・ソルバーが使用）。
- **固定シフト** `fixed_shifts`：毎週決まった曜日・時間の勤務。

## 固定シフトの扱い（両エンジン）

- **生成時に最優先で先に配置**する（承認済みお休みと重なる日は除外）。
- ただし **`max_hours_per_week`（週の上限時間）は固定シフトにも効く**。上限を超える分は
  配置せず、外した件数と対象者を警告に出す。
  （以前は固定シフトだけ無条件に置いていたため、固定シフトを入れすぎると
  本人の週上限を超えたまま総労働時間だけが膨らんでいた。）
- 非加入者の週30時間ラインは固定シフトには**適用しない**（オーナーの明示指定を尊重する）。
  超えた場合は警告のみ出すので、固定シフトを減らすか社保加入で対応する。
- ソルバー：固定シフトを先に確定 → その分を必要人数から差し引いて残りを埋める。
- Claude：各スタッフの「固定シフト」欄をプロンプトに渡し、絶対制約として毎週配置させる。
- ※「固定シフトを展開」ボタン（`expandFixedShifts`）は、生成とは別に固定シフトだけを
  カレンダーへ一括コピーする従来機能。生成が固定シフトを内包するようになったため、
  通常は生成だけで固定分も入る。

## 労働時間の数え方（拘束 と 実働）

**シフトの時間はすべて「実働」（休憩の自動控除後）で集計する。** 給与計算と同じ
数え方なので、シフト画面の合計時間と給与明細の実働時間がそのまま比較できる。

| 用語 | 意味 | 例（早番 09:30–19:00） |
|---|---|---|
| 拘束 | シフトの開始〜終了 | 9.5h |
| 休憩 | 8時間超→60分／6時間超→45分（自動控除） | 60分 |
| 実働 | 拘束 − 休憩。**賃金と社保判定の対象** | 8.5h |

ルールは `src/lib/work-hours.ts` に一本化し、シフト生成・給与計算の両方から使う。
シフト画面の「スタッフ別 合計勤務時間」は実働を大きく出し、拘束と勤務日数を併記する。

> 以前はシフト画面が拘束のみを出していたため、同じ月でも「シフト912h / 給与727h」の
> ように比較できない数字になっていた。差の大半は休憩（1人1日1時間）だった。

## 1日の所定勤務時間（standard_shift_hours）

正社員のように 1日の勤務時間が決まっている人に、スタッフ詳細で設定する（拘束・時間）。

- 例：**8.5** → 8.5時間勤務・休憩60分・**実働7.5時間**。
- 必要人数の枠や固定シフトがこれより長くても、**この長さに縮めて**割り当てる。
  - 早番（20時より前に終わる枠）：開始はそのまま、終わりを早める（09:30–19:00 → 09:30–18:00）。
  - 遅番（20時以降に終わる枠）：終わりはそのまま、開始を遅らせる（12:30–22:00 → 13:30–22:00）。
  - 閉店・開店が空かない側を固定する、という考え方。
- 縮めても「その枠を埋めた」と数えるので、同じ枠に別のスタッフが重ねて入ることはない。
  空いた時間帯（上の例なら18:00–19:00）は、重なっている遅番がカバーする前提。
- 縮めた件数・内容は生成結果の警告に出る（`GenerateResult.trimmed`）。
- 未設定（null）なら従来どおり、枠／固定シフトの長さのまま。

固定シフト展開（`expandFixedShifts`）・ソルバー・Claude生成のすべてに効く。

## 社会保険の扱い（両エンジン）

`profiles.shaho_enrolled` を生成に反映する（ライン＝**週30時間の実働**）。

- **週の区切りは暦の週（月〜日）**。`mondayKey()` で判定する。「月内の1〜7日」のような
  固定バケットだと、月初の曜日によって2つの実際の週にまたがり判定がすり抜ける。
- **週平均は「月 × 12 ÷ 52」**（`weeklyAverageFromMonthly()`）。月内の週数で割ると、
  月末の半端な週の分だけ平均が低く出て30時間の判定が甘くなる。
- **加入者**：週30時間以上を確保するよう最優先で配置（ソルバーはスコアで強く優先／
  Claudeは絶対制約）。月末に週平均30h未満なら警告を出す。
- **非加入者**：週30時間未満に抑える（ソルバーはハード上限／Claudeは絶対制約）。
  意図せず30hを超えると社保加入義務が発生し会社負担が増えるため、これを防ぐ。
- 定数 `SHAHO_WEEKLY_HOURS = 30`（`solver.ts`）。判定の最終確認は給与画面「社会保険 加入判定」。

## 生成の流れ

1. 期間（年月）を作成 → 希望・必要人数・固定シフト・社保設定を用意。
2. 「シフト作成」画面で生成（ソルバー or Claude）。
3. 不足枠（shortages）・社保未達などの警告を確認。
4. 手直し → 公開。
