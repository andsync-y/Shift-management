# 欠勤記録（欠勤・無断欠勤・遅刻・早退）

シフトが入っていた日に休んだ／遅れた記録を残す。運用は
**スタッフからLINEでオーナーに連絡 → オーナーが管理画面に登録**。

`/admin/absences`（運営 > 欠勤記録）。

## 「休み希望」との違い

| | 休み希望 `time_off_requests` | 欠勤記録 `absences` |
|---|---|---|
| 何か | シフトを組む**前**の申請 | 入っていたシフトに対する**事実** |
| 承認 | あり（pending/approved/rejected） | なし（記録するだけ） |
| シフト | 承認されれば最初から入らない | 入っていたが来なかった |

別テーブルにしているのはこの性質の違いによる。休み希望が承認されて生じた
穴は出勤打診エンジン（`docs/SHIFT_OFFER.md`）が埋める。

## 区分

| 値 | 表示 | 欠勤数に数えるか |
|---|---|---|
| `absent` | 欠勤 | ○ |
| `no_show` | 無断欠勤 | ○ |
| `late` | 遅刻 | × |
| `early_leave` | 早退 | × |

**遅刻・早退は出勤しているので欠勤数には含めない**（画面では別の列で見る）。

`no_show` は「連絡が無かった」こと自体が記録なので、`reported_at`（連絡を
受けた日時）は保存時に強制的に NULL にする。

## 画面

1. **スタッフ別サマリ（上）** — 区分ごとの件数・出勤予定日数・欠勤率。
   0件の人も出す（誰が休んでいないかも見えるように）。欠勤率10%以上は赤字。
2. **記録する（中）** — スタッフ／日付／区分／連絡を受けた日時／理由／補足。
3. **記録一覧（下）** — 直近200件。削除可。

`unique (staff_id, absence_date, kind)` で、同じ日・同じ区分は upsert により
上書きされる（登録し直しても二重に増えない）。同日の「遅刻」と「早退」は
別レコードとして両方持てる。

### 欠勤率
```
欠勤率 = (欠勤 + 無断欠勤) ÷ その月のシフト日数
```
分母は `shifts` の当月の日数（同じ日に2枠あっても1日と数える）。
シフトが0日なら「—」表示（ゼロ除算しない）。

## 給与との関係

**この記録は給与を一切変えない。** 賃金は実打刻（`time_records`）ベースなので、
休んだ分は自動的に支給されない。二重に引かないよう、給与計算からは参照しない。

## 何に使うか

- 労務管理（出勤率の把握・指導の記録）
- **社会保険の資格の説明**。所定労働時間で加入判定しているスタッフが実績で
  30時間を恒常的に下回っていないかを、欠勤記録で説明できるようにしておく
  （`docs/PAYROLL.md` の社保判定を参照）

## 権限

- オーナー：全操作
- 本人：**自分の記録のみ閲覧可**（身に覚えのない記録が残らないように）

監査ログ（`audit_trigger`）の対象。
