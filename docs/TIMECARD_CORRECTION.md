# 勤怠の補正表示（管理画面「勤怠」）

打刻をあとから直した記録を、管理画面の勤怠一覧で見分けられるようにする仕組み。

## 何を「補正」とするか

出勤・退勤の時刻が、**入力した時点より過去の時刻**で記録・変更されたものを補正とする。

- 例）打刻を忘れて、あとから管理画面で出勤 9:30 を入力した
- 例）前日の退勤を、翌朝に 21:30 に直した
- LINE（LIFF・トーク）・キオスクの打刻はサーバー時刻（＝今）で記録されるので補正にならない
- 入力時刻が今から5分以内なら補正にしない（通信遅延などのずれを許容）
- 一度付いた補正は消えない（あとで別の値に直しても、補正した事実は残る）

## データ

`time_records` に2列を持つ（`supabase/migrations/0049_time_record_corrections.sql`）。

| 列 | 意味 |
|---|---|
| `in_corrected` | 出勤が補正された |
| `out_corrected` | 退勤が補正された |

判定は DB のトリガー `trg_time_records_mark_corrected` が行う。アプリのどの経路から書いても
同じ基準になる。

管理画面の編集は分単位（datetime-local）で送られてくる。トリガーは、分が変わっていない時刻は
元の値（秒・ミリ秒まで）を残す。片側だけ直したときに、触っていない側が補正扱いになるのを防ぐため。

### 導入前の記録（推定）

トリガー導入前の記録は、マイグレーションで次の基準で推定して埋めた。

- 打刻はミリ秒まで記録されるので、秒・ミリ秒がちょうど0の時刻は管理画面で入力・変更されたもの
- そのうち、最後に保存された時点より5分以上前の時刻を補正とみなす

導入前は片側を直すともう片側の秒も落ちていたため、過去分は実際には直していない側まで補正と
表示されることがある。

## 表示

勤怠一覧の名前の横にバッジを出す。

| バッジ | 意味 |
|---|---|
| `補正` | 出勤・退勤の両方を補正 |
| `補正・出` | 出勤だけ補正 |
| `補正・退` | 退勤だけ補正 |
| `手動` | 管理画面で追加したが、その場の時刻で入れたので補正ではない |

CSV 出力には「補正」列（出勤／退勤／出勤・退勤）を足している。
